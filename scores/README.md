# 人工编配与制谱文件

这里保存可编辑的 `paijian-score` JSON 文件。它们直接记录声部、音高、时值、和弦、滑音和反复，不经过 MIDI 主旋律提取。

`heixiu-rhapsody.json` 按用户提供的《嘿咻狂想曲》图片人工录入。原图原样保存在 `heixiu-rhapsody-original.jpg`，包含“来音制谱app”水印；图片没有标明作曲或编配作者。本条目不套用仓库代码的许可或 Mutopia 数据的公版/CC 许可。

核对：原谱 29 小节、189 个音高事件、两个声部；13–20 小节反复一次，展开为 37 小节、245 个音高事件、148 拍；21–28 小节共 12 处向上滑音。试听的滑奏音间隔约 35ms，是演奏近似值，图片未指定间隔。

## 永久发布自己制作的曲谱

1. 在 `composer.html` 制谱，填写曲名和署名，确认所有小节节拍正确。
2. 点击“导出 JSON”保存可编辑原稿。SVG 是展示文件，不能代替 JSON 原稿。
3. 在仓库目录执行：`node tools/add-score.cjs /path/to/song.json my-song`。该命令会完整校验曲谱，写入 `scores/my-song.json` 并加入 `curated/index.js`，不会自动提交或推送。
4. 核对文件后提交到 GitHub 的 `main` 分支。现有 GitHub Pages 会自动部署，曲库中可找到新曲，也可通过 `score.html?score=my-song` 打开。

也可将导出的 JSON 交给网站维护者完成第 3–4 步。只上传 JSON、没有更新目录索引，尚不会出现在曲库中。

浏览器草稿、收藏都是当前设备/浏览器的本地数据；清理网站数据、使用隐私窗口或换设备可能无法找回。下载 JSON 是个人备份；提交进仓库才是公开网站的持久版本。静态网页本身没有获得 GitHub 写权限，不会直接修改仓库。

## JSON 记法

`format` 为 `paijian-score`，`version` 为 `1`；包含 `title`、`bpm`、`meter`、`instrument`、`voices`、`repeats` 和 `credits`。

每个声部的 `notation` 用 `|` 分小节、空格分音符：`1` 为一拍，`1:0.5` 为半拍，`1'` 高一个八度，`1''` 高两个八度，`1_` 低一个八度；`0` 为休止，`1:4` 为四拍长音；`(1,3,5)` 为和弦，`~(1,3,5)` 为从低到高的滑奏。每小节必须满拍，不会静默截取或补错拍。

`repeats: [{"startBar":13,"endBar":20,"times":2}]` 表示第 13–20 小节总共演奏两次。印刷谱保留反复线；试听展开，不重复印刷整段。所有声部的小节数必须一致。
