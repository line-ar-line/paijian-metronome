# 用户体验评审 · 2026-11-16

按用户要求，由一个独立 agent 模拟普通卡林巴用户，使用真实浏览器体验线上 `ec977bc`。视口为手机 390×844、桌面 1440×900，覆盖《嘿咻狂想曲》练谱、循环定位、曲库搜索/收藏/返回/最近练习，以及首次点选制谱。评审未写入真实账号或云端数据。

| 优先级 | Before | After | Why |
| --- | --- | --- | --- |
| P1 | 手机容器 354px，普通谱页宽 504px，右侧音符需要横滑，但专注模式隐藏了提示 | 默认适合屏宽，最低约 21px 数字；密集页显示横滑提示，开启跟随时追踪发声音符 | 跟练时能看清正在弹的音，兼顾密集谱的可读性 |
| P1 | 第 2–3 小节循环时点击第 5 小节，静默回到第 2 小节；循环状态藏在折叠区 | 范围外点击/拖动退出循环；吸顶播放栏持续显示范围、轮次与退出按钮 | 定位符合所点位置，便于判断当前播放范围 |
| P2 | 制谱点一个音后，缺拍错误在手机屏幕下方，操作区看不到原因 | 工具栏旁显示当前小节拍数、还差/超出拍数，并同步显示校验错误 | 用户能继续完成当前小节，不会把预览停用误认为输入失败 |
| P3 | 最近练习已有记录但搜索无匹配，仍提示“播放一首曲子后会出现” | 区分空历史与筛选无匹配，支持清除搜索后保留最近练习视图 | 清楚表明已有记录仍在 |

搜索《嘘》、收藏、打开正确曲目、返回保留查询、最近练习记录、桌面谱面和手机吸顶暂停入口在初次评审中均通过，维持当前交互。

自动化验证包括 `tests/practice-ui.browser.cjs` 新增的四项体验回归、`tests/measure-progress.test.cjs` 的未完成小节/和弦/滑音/复合拍号校验，以及既有播放定位、收藏、制谱存储和导出检查。屏幕缩放与纸面导出保持分开。
